Payloads are generated agent files associated with a listener and campaign. A payload is built by the TeamServer using the configuration supplied during payload creation and is stored by the TeamServer after successful generation.

### Prerequisites
Before generating a payload, ensure that:
- A listener is available to provide the payload's communication configuration.
- A campaign is available for the payload to be associated with.
- The selected architecture is supported by the payload build environment.
- The TeamServer is able to access the required payload build tools and Agent source.
A payload cannot be generated if the specified listener cannot be found. Payload generation can also fail if the payload build process or compiler configuration is unavailable.

### Generating a Payload

A payload is generated by providing the TeamServer with the payload configuration.

The current payload configuration contains:

|Setting|Description|
|---|---|
|Name|Name assigned to the generated payload.|
|Listener|Listener associated with the payload.|
|Campaign|Campaign associated with the payload.|
|Architecture|Target architecture used when building the payload.|
|Type|Payload type requested for the generated payload.|

The currently supported payload configuration uses the `x64` architecture and `winexe` payload type.
The TeamServer first validates the supplied listener and then creates a unique identifier for the payload. The payload builder uses this identifier together with the listener configuration when preparing the build.
The payload is then compiled by the TeamServer. Once the build completes successfully, the generated file is copied into the TeamServer's `Payloads` directory and a payload record is saved in the database.

### Payload Type
The current payload generation process supports the `winexe` payload type.
The payload builder searches the build output for the generated executable and copies the resulting `.exe` file into the TeamServer's `Payloads` directory.

### Architecture
The current payload generation process supports the `x64` architecture.
The payload builder uses the configured `x64` compiler when building the Agent. If a suitable compiler cannot be selected or the build environment cannot complete the compilation, payload generation fails.

### Generated Payloads
After a successful build, the TeamServer registers the payload with information including:
- Payload filename
- Payload type
- Architecture
- Associated listener
- Associated campaign
- Creation time
The TeamServer also records the payload in its database. The generated payload file is stored under the TeamServer's `Payloads` directory.
The generated file's size can be determined from the stored payload file. If the file cannot be found in storage, its reported size is `0`.

### Payload Generation Errors
Payload generation may fail for several reasons, including
- The selected listener does not exist.
- The required compiler is unavailable.
- The CMake configuration fails.
- The payload compilation fails.
- The generated executable cannot be located.
- The generated payload cannot be copied into the payload storage directory.
When generation fails, the TeamServer reports the generation failure rather than completing the payload creation process.

### Payload Management Workflow
The overall payload generation process is:
1. Select the required listener and campaign.
2. Provide the payload name and configuration.
3. Submit the payload generation request to the TeamServer.
4. The TeamServer validates the listener.
5. The payload builder configures and builds the Agent.
6. The generated payload is placed in the TeamServer's `Payloads` directory.
7. The payload metadata is saved to the database.
